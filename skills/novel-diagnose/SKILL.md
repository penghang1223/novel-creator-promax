# 小说数据诊断

## 边界

拥有数据诊断、阶段判断、修复顺序、断流急救和切书建议；不改正文、不改大纲、不替代审稿或写作流水线。

项目内的数据接入与输出路径使用 `data-diagnosis` 技能；方法论仍以本技能为准。

涉及“纯 AI 投稿能不能赚钱 / 平台治理 / 朱雀检测环境”时，先读 `${CLAUDE_PLUGIN_ROOT}/knowledge_base/60_Platform/AI变现与平台治理现实.md`；不承诺收益，不提供绕过检测的方案。

## 禁止事项

- 缺少 11 项关键数据时，不给处方；信息不足时的建议一定是废话。
- 不把单个案例推广成整体结论。
- 不承诺流量、收益或签约结果。
- 不在同一天同时改书名、简介、封面和正文；七天里只动一件事，否则测不出因果。

## 强制流程

1. 先向用户要齐 11 项数据：

```text
总字数 / 当前在读 / 书架比 / 追更比 / 前 10 章完读率 / 10 万字完读率 /
7 日追更人数 / 日均更新 / 断更天数 / 作品评分 / 点击率或曝光量
```

2. 把数据写成 JSON 或 Markdown，运行：

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/tools/data_diagnosis.py" --input 数据.md --json
```

3. 按阶段解释，不要跨阶段修错东西：

| 阶段 | 字数 | 当前唯一考核项 |
|---|---|---|
| L1 | <8 万 | 签约 / 首章留存 |
| L2 | 8-10 万 | 验证期指标 |
| L3 | 10-20 万 | 首秀池完读率 |
| L4 | 20-50 万 | 书测与中期留存 |
| L5 | 50-100 万 | 长线追更与收益 |
| L6 | 100 万+ | 完本与 IP |

4. 按修复七步排序：止血 → 门面 → 前 300 字 → 第一章 → 前三章 → 10 万字完读 → 长线结构。

5. 输出：阶段、最严重指标、七天动作。只给一个主行动，其余排期。

## 断流急救

| 症状 | 先查什么 |
|---|---|
| 曝光归零 | 是否断更/改已发布章/触发红线；门面是否被改坏 |
| 点击掉一半 | 书名、封面、简介；进书测 |
| 完读掉一半 | 前 300 字、前三章兑现与代价 |
| 书架比恶化 | 章末钩子、熟人线 |
| 追更断 | 连续同温、爽点断供 |
| 评分下滑 | 20 条毒点、逻辑与人设 |

## 切书决策

满足以下情形才建议切书：三次评估全败且书测两次无效；20 万字后仍低于及格线且单位字数收益明显偏低；核心设定已写死，修复成本高于重开；题材被平台治理或赛道衰退；作者本人无法维持更新。

切书前先算三笔隐性成本：账号权重、老读者流失、存稿浪费。

## 数据引用纪律

引用任何数字前确认五件事：时间、单位、样本、口径、比较对象。百分比与百分点分开说；平台口径与第三方口径不混排。
