# 续写他人作品

从用户提供的文本继续写作。拆文和推断都不是作者确认的事实；未经用户审查不得把推断写成原作设定。

## 两种模式

| 模式 | 适用 | 入口 | 产物 |
|---|---|---|---|
| A. 项目续写 | 原文较长、要连续写多章、需要记忆和门禁 | `continuation_import.py` + `continuation-gate` | 可续写项目、真相文件、续写门禁 |
| B. 片段续写 | 用户只给一段/一章，只要接着写一段；不建项目 | 本技能的模式 B 流程 | 续写交接、续写正文、接缝检查 |

先判断模式；用户没有明确说“建项目/继续连载”时，默认模式 B。需要长期连载时再从 B 转 A。

## 边界

| 拥有 | 不拥有 |
|---|---|
| 原文分析、接续方案、续写正文 | 改写原作品、版权判断、平台发布授权 |

- 只处理用户有权续写的文本；不主动复制或传播原文。
- 模式 A 的产物写入工作区 `素材/拆文/`、`novel_output/{平台}/{书名}/`。
- 模式 B 的产物写入工作区 `素材/`；不写正式项目正文目录，除非用户明确要求转为模式 A。
- 续写门禁与长篇 `seal` 是两个门：`continuation-gate` 只记录导入检查，不声称立项清单通过。

## 模式 A：项目续写

1. **确认工作区**：

   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/tools/workspace.py" --workspace "${CLAUDE_PROJECT_DIR}" status --json
   ```

   `dangerous=plugin_root|root` 时停止；未确认且无存量书时先让用户确认。

2. **导入与拆文**：

   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/novel_creation_promax/scripts/continuation_import.py" \
     --input "{原文文件或目录}" --title "{书名}" --platform "{平台}" --genre "{题材}" \
     --confirm-workspace
   ```

3. **审查报告**：读 `素材/continuation_import_report.md` 和 `设定/` 下的导入内容，向用户列出：
   - 已识别：章节数、角色、地点、势力、关系
   - 缺口：地点/势力/关系缺失、动机与能力边界未说明
   - 需要用户确认：主线终点、卷结构、伏笔回收、角色动机

4. **补齐细纲**：和用户一起填写 `细纲/续写细纲.md`，至少写清下一章的目标、冲突、爽点、伏笔和截断点。不得用拆文统计直接充当细纲。

5. **解锁正文**：用户确认报告后：

   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/novel_creation_promax/scripts/project_bootstrap_pipeline.py" \
     continuation-gate --novel-dir "novel_output/{平台}/{书名}" --approve
   ```

6. **写续写章**：用 `novel-chapter-write` 流程。章节号从原文最后一章 + 1 开始；首章仍必须跑 `write_pipeline.py pre`。

## 模式 B：片段续写（不建项目）

1. **定位原文**：确认原文、接续位置、目标长度和限制。用户指向外部页面时获取可访问原文并记录来源；只有书名或缺失接续段时，先完成可核实分析，请用户提供原文，不凭记忆假装读过。
2. **写续写交接**：按模板 `${CLAUDE_PLUGIN_ROOT}/novel_creation_promax/references/templates/continuation_handoff.md` 写 `素材/续写交接.md`，分列：
   - 原文事实：最后事件、时间地点、视角时态、在场人物、资源状态、未解冲突、伏笔
   - 合理推断：有依据但未被原文确认的内容
   - 拟新增设定：本段需要但不属于原文的内容
3. **提取叙事特征**：视角距离、句段节奏、对话密度、信息揭示方式、情绪基调。需要定量基线时使用 `skills/novel-memory/scripts/style_dna_extractor.py`，先看 `--help`，不臆造参数。DNA 指标只描述风格，不能证明事实衔接正确。
4. **形成接续场景卡**：本段目标、冲突、截断点、新增设定。对剧情走向有决定作用的未知设定先向用户澄清；其余用低承诺写法，避免提前锁死。
5. **两遍写作**：Pass 1 完整行动与冲突；检查逻辑、人物知情范围、伏笔公平性；Pass 2 清理 AI 表达。以原创表达续写，不复述大段原文，不声称补写内容属于原作者。
6. **接缝检查**：人物知情范围、动作位置、时间连续、动机声纹、能力限制、未解伏笔。按目标项目实际门禁审计；没有项目时用人工检查，并记录脚本覆盖范围。
7. **交付**：续写正文、摘要、接缝检查、新增事实清单。需要长期管理时转模式 A。

## 输出

模式 A：

```text
${CLAUDE_PROJECT_DIR}/
├── 素材/拆文/{书名}/
├── 素材/continuation_import_report.md
└── novel_output/{平台}/{书名}/
    ├── 设定/
    ├── 细纲/续写细纲.md
    ├── 记忆/style_dna_baseline.json
    ├── 素材/continuation_import_gate.json
    └── 摘要/workflow.json
```

模式 B：

```text
${CLAUDE_PROJECT_DIR}/素材/
├── 续写交接.md
├── 续写正文_{YYYY-MM-DD}.md
└── 续写检查.md
```

## 硬规则

- 拆文记录和模式 B 的推断一律标记为“推断”；不能当作已确认事实写进正文。
- 模式 A 未经 `continuation-gate --approve`，不得写正文。
- 章节号必须衔接原文最后一章；不得从头重编号。
- 角色名、专名、称呼以原文为准；不得混入其他项目设定。
- 原文未说明的设定，先问用户，不得自行补成硬设定。
- 不把未读章节、未访问全文或猜测的结局标记为已知。
- 不凭风格相似跳过逻辑与人物检查；DNA 不能替代事实衔接。
- 不覆盖原文、不自动发布、不把原文全文存入通用知识库。

## 禁止事项

- 不续写用户无权处理的文本。
- 不把拆文统计当成细纲或人物小传。
- 不跳过用户审查直接解锁门禁。
- 不伪造 seal、审计记录或 commit。
- 不把模式 B 的片段直接写进正式项目正文目录。
- 不承诺续写作品能发布、签约或获利。
