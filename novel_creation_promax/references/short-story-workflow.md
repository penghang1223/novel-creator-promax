# 短篇创作工作流

适用于 `short-story` 和短篇 `free-create`。本文件定义短篇写前准备和整篇验收；正文两遍写作、逻辑与人物优先级沿用 [编排器](orchestrator.md)，不新建章节状态机。

## 1. 明确任务

- 从对话和已有项目提取平台、题材、读者、整篇目标字数、分章方式、投稿/签约目标、用户指定创意与禁区。
- 平台未指定按仓库默认番茄；篇幅未指定先给出暂定预算并记录依据，不能把长篇单章字数当作短篇整篇长度。
- 已有作品续写或修改，先读原文、原策划和反馈。除非更换平台、题材或核心卖点，不重复全套市场调研；核查相关规则和缺口即可。

## 2. 调研先行

新作默认调用共享调研技能 `${CLAUDE_PLUGIN_ROOT}/skills/novel-market-research/SKILL.md`，scope=short-story，输出 `{小说目录}/素材/短篇调研.md`。来源记录、至少 3 篇样本、实际阅读范围、评论证据和创作决策的要求统一在该技能维护；知识预读由 `${CLAUDE_PLUGIN_ROOT}/knowledge_base/_ROUTING.md` 分发，不以本地趋势资料代替实时核查。

已有调研可复用，但必须检查来源是否仍可用、平台规则是否变化、样本是否覆盖本次题材。网络不可用或样本不足，先完成可做部分并列明缺口，停在策划阶段；用户明确同意有限资料试写后，记录范围再进入正文。用户明确要求纯练笔或跳过调研时，记录本次豁免，不反复询问，不宣称完成市场验证。

## 3. 短篇策划与写前检查

调研完成后写入 `{小说目录}/outline.md`：

- 一句话卖点、目标读者、差异化、总字数及场景/分章预算。
- 人物欲望、恐惧、动机、行动边界；悬疑/灵异另列规则及代价。
- 完整因果链：触发事件→主动行动→阻碍升级→关键选择→高潮→后果。
- **先锁结局/谜底，再倒推铺垫**：每条关键线索的出现位置、读者当时的理解、回收位置；区分事实、误导和角色误判。
- 开篇钩子、情绪节拍、核心反转、结尾兑现；反转必须有前置依据，不能靠临时新增规则解围。

在 `{小说目录}/素材/短篇写前检查.md` 逐项记录证据位置和通过/未通过：任务边界、调研或明确豁免、差异化、人物动机、因果链、结局可解释、线索可回收、篇幅预算、9问≥70、红线。不得用空模板或“已检查”代替具体答案。有缺口先补齐，不动笔。

这是助手执行的检查清单，**不是已接入 Python 的自动门禁**。已获授权的常规准备连续完成，无需逐步确认；核心方向选择、原细纲偏离按编排器和用户授权处理。

## 4. 正文与修订

1. 按场景卡写 Pass 1，优先完整行动、冲突和后果，在计划截断点结束。
2. 检查剧情逻辑、人物动机、信息可知范围和伏笔公平性，修复后再进入 Pass 2。
3. Pass 2 清理 AI 表达、口语语域和重复，不机械清零常用词，不破坏证据链与声纹。
4. 整篇审稿：开头承诺是否兑现、每场是否推进、反转能否回看成立、结尾是否解决核心冲突、有无凑字和解释过量。
5. 修改后重新检查受影响线索与结尾，记录 `novel_state.json` 的 `revision_history`。

### 与现有脚本的边界

- 已完成合法 bootstrap/seal 的项目，继续使用 `write_pipeline.py pre/post` 及 Gate，保留原有审计、真相回填和 commit 要求，不降低门禁。
- 独立短篇不得为了调用流水线伪造 `workflow_gate`，也不要生成无意义的 8 卷细纲。尚无独立短篇 seal；采用上述人工写前检查与整篇审稿，交付时明确脚本覆盖范围。
- `post_write_audit.py` 当前固定使用 2800–3200 中文字符等阈值；独立运行的结果只作诊断。短篇按本篇预算和核实的平台要求逐项复核，记录不适用项及依据，不把脚本失败改写为通过；已纳入章节流水线的硬失败仍需按原流程解决。

## 5. 交付与复盘

交付前必须有：正文、`{小说目录}/outline.md`、调研记录或用户豁免、写前检查、`{小说目录}/素材/短篇审稿.md`。审稿记录整篇中文字符数、逻辑/人物/伏笔/结尾检查结果、脚本结果及适用性、未解决问题。阻断项未解决不得标为定稿。

摘要和状态变化同步到项目记忆及 `knowledge_base/80_Projects/`，不把全文复制进知识库。发布沿用独立发布入口及授权规则；获得真实投稿/读者反馈后，记录“原预期→实际反馈→下次调整”，没有数据不虚构转化率。
