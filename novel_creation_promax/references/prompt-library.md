# 提示词库（24 组）

> 来源：novel-engine v3.0.2（MIT），按本项目结构改写；字数与平台口径以 `knowledge_base/60_Platform/_PROFILES.json` 为准。
> 本库提供“具体场景指令”，不替代 `context-agent` 五段任务书、rule_stack、9 问和审稿。

## 一、使用原则

1. 给方向、经验、具体约束，不给指标、格式和验收清单；读起来像验收标准，AI 就交应试作文。
2. 一次只给本章需要的信息，不把整本设定塞进去。
3. 不给“写得自然一点”“要有感染力”这类愿望；给可执行的动作。
4. 提示词不是逐字模板；每次按本书设定改 40%。
5. 不让 AI 决定“这一章写什么”；剧情走向由作者拍板。

## 二、24 组提示词

### 创作类

| # | 场景 | 关键约束 |
|---|---|---|
| 1 | 章节初稿 | 目标字数 + 本章必须发生的一件事 + 章末停在未完成 + 禁总结段 |
| 2 | 续写 | 先复述上一章末尾三件事（位置/状态/未完成），再往下写；禁另起线索 |
| 3 | 场景扩写 | 只扩这一场，不加新人物、不加新设定；扩的是行动与反应，不是形容 |
| 4 | 章节压缩 | 保留全部事件与因果，删描写与重复；目标压缩到 70% |
| 5 | 内心戏 | 只写他此刻能想到的，不写全知判断；心理必须落到一个动作上 |
| 6 | 环境描写 | 三句以内，必须服务当前情绪或伏笔；禁天气开场式铺陈 |
| 7 | 打斗 | 三回合内必须有变化（位置/伤势/规则/心态至少一项）；禁招式说明书 |
| 8 | 对话 | 给双方各自的目的，不许直接说出目的；允许答非所问 |

### 设计类

| # | 场景 | 关键约束 |
|---|---|---|
| 9 | 人物卡 | 四问必答（对谁退让/对什么撒谎/擅长什么/总在哪犯错）+ 眼下要办的事 |
| 10 | 反派设计 | 他的行为在他自己的逻辑里必须成立；与主角共享同一个伤口 |
| 11 | 人设反差 | 一句「本该…却…」+ 三个可验证的落地细节 |
| 12 | 分卷大纲 | 每卷给：卷末必须交付什么 + 主角质变点 + 新层级 |
| 13 | 章节作战表 | 每章一行：事件 / 爽点类型 / 钩型 / 信息增量 / 情绪档 |
| 14 | 伏笔台账 | 编号 + 埋设章 + 计划回收章 + 回收方式；回收周期 ≤100 章 |
| 15 | 开篇三句 | 异常 + 代价 + 反应；不许出现天气、梦、自我介绍 |
| 16 | 第一章工程化 | 按四窗口交付，每窗给一句验收问题 |
| 17 | 章末钩子 | 指定 H 型号；禁反问、禁感叹、禁平收 |
| 18 | 爽点排布 | 按 1:1.5:0.5 配比写一段，余韵必须落在旁观者反应上 |

### 包装类

| # | 场景 | 关键约束 |
|---|---|---|
| 19 | 书名 | 出 12 个，标注用了哪一式；8–14 字；禁抽象意境 |
| 20 | 简介 | 4 段式，字数与分段口径见 `书名与简介.md`；前 3 行必须出冲突 |
| 21 | 标签 | 一个大热度 + 两个精准 + 一个趋势，总数 ≤5，各写一句理由 |

### 质检与诊断类

| # | 场景 | 关键约束 |
|---|---|---|
| 22 | 去 AI 味 | 只改命中的句子，不重写全篇；交差异清单 |
| 23 | 16 维审核 | 只报问题不给改稿；每维一句结论 + 一条可执行建议 |
| 24 | 数据诊断 | 先要 11 项数据；按「先修最前端」排序；一次只给 1 条主建议 |

## 三、五条禁忌

1. 不许写「写得精彩一点」「要有感染力」——这是愿望，不是指令。
2. 不许同时要求「简洁」和「细节丰富」。
3. 不许要求「模仿某作者」；可以要求「学他的节奏」。
4. 不许把整套规范一次性塞进提示词，会互相抵消。
5. 不许让 AI 自己决定「这一章写什么」。

## 四、提示词自检

写完后逐条问：

- 这条指令能不能被执行？还是只是形容词？
- 它有没有和 rule_stack、任务书、平台字数冲突？
- 它有没有要求 AI 做创作决策，而不是执行决策？
- 它有没有泄露未揭示事实或角色未知信息？

## 五、与现有流程的关系

- `context-agent` 负责五段任务书：开篇委托、这章的故事、这章的人物、怎么写更顺、收在哪里。
- 本库负责具体场景指令：写初稿、续写、扩写、对话、钩子、审核、诊断。
- `write_pipeline.py pre` 负责知识包、记忆包、9 问和 rule_stack；提示词不能替代这些门禁。
- 提示词产出仍要经过 `writing_gate.py`、`post_write_audit.py` 和结构化审稿。
