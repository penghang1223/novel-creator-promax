# 插章与重编号

> 用途：给已按序号编号的长篇插入新章（扩写、放慢节奏、加情节），并安全重编号。
> 边界：本文件是操作协议；实际修改前必须备份正文和细纲。

## 一、核心难点

1. 整块插入会破坏重编号。
2. 插错位置导致章号错位。
3. 插章破坏"仅主角知晓某秘密"类铁律。

## 二、必做步骤

1. **备份原文**：正文、细纲、摘要、passport、commit 全部先快照。
2. 选插入位置：`before_num` 用目标段内现有章号，表示"插在这一章之前"。
3. **DESC 顺序插入**：从高章号往低章号插，低号不扰动高号行位置。
4. **逐行插入**：新章正文必须 `split('\n')` 后逐行 insert，整块插入会塌成一行。
5. 整体重编号：保留标题文字，只改章号。
6. 重跑派生：细纲、摘要、passport、commit、记忆、索引。
7. 校验：章号连续、无空章、无残留旧词、秘密没有被配角说破。

## 三、插入校验

```python
nums = [int(m.group(1)) for line in text.split("\n")
        if (m := re.match(r"^\s*第\s*0*([0-9]+)\s*章", line))]
assert nums == list(range(1, nums[-1] + 1)), "章号不连续！"
```

## 四、铁律审计

遍历每章正文，对每个配角专名检查：同一句（按 `。！？\n` 切分）内不得同时出现配角名与秘密元素。

- 主角可以在内心独白提及。
- 配角绝不可说破。
- 新章里把秘密来源写成"自家琢磨的心得/秘籍指的路"可以安全绕过。

## 五、坑位清单

| # | 坑 | 规避 |
|---|---|---|
| 1 | 整块插入塌行 | 务必逐行 insert |
| 2 | 升序插入错位 | 务必 DESC 顺序 |
| 3 | 编码错误 | 读写统一编码，脚本本身 UTF-8 |
| 4 | 粗纲范围过期 | 按内容锚点重新定位 |
| 5 | 插章卡时间线 | 注意前后时期的用语/称谓变化 |

## 六、改名注意事项

批量改名按 old 长度降序逐词替换，避免子串错替；书名号内或含关键词的行要 skip 保护（如"金戒指"≠"金手指"）。

## 七、与项目流水线的关系

插章会改变章号，必须同步：

- `正文/` 文件名
- `细纲/` 对应章节
- `摘要/chapter_NNN_*.json` 与 passport
- `素材/commits/` 提交记录
- `novel_state.json` 章节表
- 记忆与知识库项目索引

插章后必须重跑 `write_pipeline.py pre/post`，不能只改文件。
