# 小说创作知识库 (Knowledge Base)

> Obsidian 协作式结构化知识管理系统
> 所有创作知识集中于此，支持双向链接与标签检索

---

## 目录结构

```
knowledge_base/
├── _STRUCTURE.json        # 目录与生命周期契约（机器可读）
├── _ROUTES.json           # 机器可读知识路由
├── _ROUTING.md            # 人读路由说明
├── 00_Index.md            # 全局索引
├── 10_WorldBuilding/      # 世界观与题材（含题材知识库/ 13 题材 + profile.yaml）
├── 20_Characters/         # 角色系统（命名/原型/弧线/反派/群像/动机/声纹）
├── 30_Plot/               # 剧情与大纲（大纲/结构/节奏/伏笔/细纲/复盘）
├── 40_Writing/            # 写作技法，按阶段编号：
│   ├── 01_开篇技巧/        # 黄金三章、开头钩子、开篇100分卡
│   ├── 02_节奏与结构/      # 工作流v2、叙事引擎、爽点分类、卡章、张力曲线
│   ├── 03_人物与对话/      # 对话质感、AI对话丰满化、乒乓球短句治疗、心理描写
│   ├── 04_场景与描写/      # 场景加厚、转场、潜台词与张力、书名简介
│   ├── 05_降AI痕迹/        # 降低AI痕迹、风格硬约束、AI禁用词句表
│   ├── 06_质量校验/        # 因果链、常识校验、插章与重编号、实战教训
│   ├── 07_短篇与模板/      # 短篇模板、体裁库、短剧改编
│   └── 风格指南/           # 风格索引 + 24 位作家风格技能合集（每位含 SKILL.md/references）
├── 50_Quality/            # 质量治理：红线检查/、评估系统/、量化门禁/、发布后复盘/
├── 60_Platform/           # 平台规则与商业情报（番茄/起点/晋江/七猫/知乎/豆瓣等）
└── 80_Projects/           # 项目级知识（每本小说一个目录）
    └── {书名}/            # _config.md + 逐步补齐项目三件套
```

当前目录统计以 `python tools/knowledge_base_audit.py` 为准，避免手工索引长期过期。

## 使用规范

### 写前读取
开始创作前，根据当前小说的题材和风格，读取对应的知识文件：
- 都市文 → `10_WorldBuilding/题材知识库/都市.md`
- 悬疑文 → `10_WorldBuilding/题材知识库/悬疑.md`
- 毒舌风格 → `40_Writing/风格指南/毒舌风格.md`

### 写后更新
剧情导致角色状态变化时，更新 `80_Projects/{小说名}/` 中的对应文件。

项目目录最低契约：`_config.md`，立项完成后补齐项目索引、变更记录、伏笔追踪、角色状态、剧情节点。

### 质量检查
每章完成后执行 `50_Quality/` 中的检查流程：
1. 章节前检查（9问）
2. 红线系统（三级红线）
3. 评估系统评分

### 语料使用
需要毒舌/搞笑内容时，参考 `40_Writing/风格指南/毒舌风格.md`，不要照搬原文。

### 平台发布

发布前阅读 `60_Platform/` 中对应平台的规则和商业情报。

## 创作工作流

立项 → 题材知识库 → 创意策划 → 角色设定 → 大纲规划

细纲 → 记忆初始化 → 正文写作（章前检查 → 写作 → 审计）

质量评估 → 记忆回填 → 发布 → 复盘

详见 `40_Writing/工作流v2.md`

## 生命周期

- 活动知识：`10_WorldBuilding/` 至 `80_Projects/` 共 7 个域。
- 项目事实：`80_Projects/`。
- 历史兼容说明：详见 `_LEGACY_INDEX.md`（全量库的历史资料已迁至 novel-creator-pro 的 `90_Archive/`，本精简库不含该域）。
