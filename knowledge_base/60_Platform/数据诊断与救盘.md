# 数据诊断与救盘

> 用途：作品上线后，用后台数据判断"病在哪"，并排出修复顺序。
> 时效：阈值与阶段划分为番茄 2026-08/09 口径；跨平台使用前替换为对应平台考核项。
> 机检：`python tools/data_diagnosis.py --input 数据.md --json`。
> 纪律：只要用户说"我扑了"，先要 11 项数据，不要直接给建议。

## 一、必采 11 项

```text
总字数 / 当前在读 / 书架比 / 追更比 / 前 10 章完读率 / 10 万字完读率 /
7 日追更人数 / 日均更新 / 断更天数 / 作品评分 / 点击率或曝光量
```

缺一项，诊断就会偏。

## 二、阶段划分

| 阶段 | 字数 | 当前唯一考核项 |
|---|---|---|
| L1 | <8 万 | 签约 / 首章留存 |
| L2 | 8-10 万 | 验证期指标（书架比 / 追更比） |
| L3 | 10-20 万 | 首秀池表现（完读率） |
| L4 | 20-50 万 | 书测与中期留存 |
| L5 | 50-100 万 | 长线追更与收益结构 |
| L6 | 100 万+ | 完本规划与 IP |

错阶段修错东西是最常见的浪费：L1 阶段去优化中后期剧情，没有意义。

## 三、阈值表（番茄口径）

| 指标 | 优秀 | 及格 | 警惕 | 极差 |
|---|---|---|---|---|
| 书架比 | ≤5:1 | 6-10:1 | 11-18:1 | >18:1 |
| 追更比 | ≤20:1 | 21-50:1 | 51-100:1 | >100:1 |
| 前 10 章完读 | ≥25% | 15-25% | 8-15% | <8% |
| 10 万字完读 | ≥15% | 8-15% | 5-8% | <5% |
| 7 日追更率 | ≥12% | 8-12% | 5-8% | <5% |

口径分歧时取更严的一档，避免自我安慰。

## 四、症状 → 病因 → 处方

| 症状 | 最可能的病因 | 处方方向 |
|---|---|---|
| 曝光低、点击低 | 门面问题 | 改书名/简介/封面，进书测 |
| 点击正常、首章完读低 | 前 300 字无异常 | 按开篇 100 分卡重修 W1/W2 |
| 首章过、第 2-3 章掉 | 无兑现、无代价 | 第三章前必须给一次完整爽点 |
| 完读正常、书架比差 | 章末无钩子 / 缺牵挂 | 补钩型轮换 + 加一个熟人角色 |
| 书架正常、追更差 | 爽点密度不足 / 温度平 | 重排温度曲线 |
| 中期掉（20 万字后） | 阶梯打完 / 换地图不换矛盾 | 开新层级或改写世界规则 |
| 数据突然断崖 | 断更 / 改已发布章 / 负面连击 | 先止血，不要改剧情 |
| 全书都好但收益低 | 字数不够 / 未进激励档 | 看平台收益门槛 |

## 五、修复七步

1. **止血**：停断更、停改稿、停深夜更新。
2. **门面**：书名 → 简介 → 标签 → 封面。
3. **前 300 字**。
4. **第一章**（完整度，不只是开头）。
5. **前三章**（兑现与代价）。
6. **10 万字完读**（中期节奏）。
7. **长线结构**（阶梯、地图、关系网）。

先修最前端。前端没修完就修后端，等于在漏水的桶里加水。

## 六、断流急救（7 天）

| 症状 | 动作 |
|---|---|
| 曝光归零 | Day1 确认是否触发红线；Day2 检查门面是否被改坏 |
| 点击掉一半 | Day2-3 换封面或书名，进书测 |
| 完读掉一半 | Day3-4 重修前 300 字与前 3 章 |
| 书架比恶化 | Day4-5 补章末钩子与熟人线 |
| 追更断 | Day5-6 检查是否连续同温、爽点断供 |
| 评分下滑 | Day6-7 检查是否命中 20 条毒点 |

Day8 起做一次书测，观察 7-10 天。**七天里只动一件事，动三件就测不出因果。**

## 七、书测与包装

### 书测 A-E 五组素材

| 组 | 测试变量 | 目的 |
|---|---|---|
| A | 原书名 + 原封面 | 基线 |
| B | 新书名 + 原封面 | 测书名点击力 |
| C | 原书名 + 新封面 | 测封面点击力 |
| D | 新书名 + 新封面 | 测组合 |
| E | 对照（不改） | 排除时间波动 |

观察 7-10 天；一次只测一个变量，否则无法归因。

### 书名 15 式（选 1 主式）

身份 + 反转、能力 + 代价、物件 + 秘密、量级 + 身份、否定 + 常规、时间 + 处境、地点 + 事件、关系 + 冲突、目标 + 阻碍、数字 + 结果、提问 + 悬念、对比 + 反差、命令 + 后果、秘密 + 揭示、日常 + 异常。

### 简介四段

1. 第一段：人物 + 处境 + 冲突（前三行必须出冲突与代价）。
2. 第二段：变化 + 代价（他做了什么，失去什么）。
3. 第三段：悬念 + 期待（读者想知道什么）。
4. 第四段：一句钩子（不要总结全文）。

### 标签三原则

- 一个大热度 + 两个精准 + 一个趋势，总数 ≤5。
- 避开"有量但已被同款占满"的标签。
- 主标签要能对上当期征文方向。

## 八、切书决策

满足以下情形才建议切书：

1. 三次评估全败，且书测两次无效。
2. 20 万字后数据仍低于及格线，且单位字数收益明显偏低。
3. 核心设定已被自己写死（阶梯打完、规则崩坏），修复成本高于重开。
4. 题材已被平台治理或赛道整体衰退。
5. 作者本人已无法维持更新。

切书前先算三笔隐性成本：账号权重、老读者流失、存稿浪费。

## 九、数据引用纪律

引任何数字前，先确认五件事：**时间 / 单位 / 样本 / 口径 / 比较对象**。

- 百分比与百分点分开说。
- 一个案例只说明一角，不许用它推整体。
- 平台口径与第三方口径不许混排；混排时必须标注。
- 后台实际结算数字优先于任何公开估算。
